## 一、数据源缺陷汇总（4 个，按严重程度排序）

### 缺陷 A 🔴 M 与 F 几乎完全共线（最严重）

| | |
|---|---|
| **实测** | `Pearson r(F, M) = 0.999984` |
| **根因** | 造数时 `订单数 ∝ scale`，而 `单均金额 ≈ 常数 × (0.9 + 0.2×随机)` → `M ≈ F × 常数` |
| **后果** | ① 图 5 散点退化成一条直线，KMeans 只是"沿对角线切段"，聚类无意义 ② **RFM 的 M 维度成了 F 的重复** —— 八分层中 M/F 判定几乎相同，一个维度被浪费 |
| **影响图** | 05（致命）、02（间接） |

### 缺陷 B 🔴 M 分布过于极端

| | |
|---|---|
| **实测** | min 0.13 亿 / 中位 0.26 亿 / max 14.23 亿；`max/中位 = 55 倍`、`max/min = 107 倍`；**偏度 8.31** |
| **根因** | 纯幂律 `w ∝ i^(-0.8)` **无上截断**，头部客户与中位数差 55 倍 |
| **后果** | 线性刻度下：图 1 除 1~2 个点外全部压成一条底边；图 3 的柱状除前 2 根全被压平 |
| **影响图** | 01、03 |

### 缺陷 C 🔴 R 不连续（双峰）

| | |
|---|---|
| **实测** | `R=0` 占 **85.0%**（255 家）；`1≤R<40` 仅 3.0%；`R≥40` 占 12.0%；36 个取值**最大间隔 65 天** |
| **根因** | 活跃度用了**二值概率**（0.9 / 0.45 / 0.10）× 353 天 → 活跃客户几乎每天都买（R=0）；沉睡客群 gap 固定 60~180 天 → R 很大。**中间没有过渡** |
| **后果** | ① 图 1 左侧一列 255 个点完全重叠，无法分辨 ② **图 2 的八分层只有 6/8 类非空**，且 176/116 对 3/3/1/1 极端失衡（因为"R 是否高于均值"只有两种结果）③ R/F/M 三分位打分在 R 上退化 |
| **影响图** | 01、02 |

### 缺陷 D ⚠️ 只植入 1 处异常

| | |
|---|---|
| **实测** | 异常月份仅 2026-06（+120.0%） |
| **后果** | 图 4 的单均折线除一个尖峰外全程平直，缺少"异常有不同形态"的层次感；对比数仓数据集有 4 个异常月（双向波动）更有说服力 |
| **影响图** | 04 |

## 二、逐图诊断

## 图 01 · 客户 RFM 分布：最近消费 vs 消费金额

**表达目标（保持不变）**：看清客户在「流失风险 R」与「价值贡献 M」两个维度上的分布，识别头部与沉睡客群。

### 现状问题
1. **左侧一条竖线**：255 个客户的 R=0，散点完全重叠在 x=0（缺陷 C）
2. **其余点在底部压成一条带**：M 轴线性刻度被顶部的 14.23 / 8.1 亿两个点撑开，98% 的点落在 0.13~2 亿区间而挤在底部（缺陷 B）
3. 图例 6 项，其中 4 类只有 1~3 家，图例本身不成比例
4. 「重要保持(3家)」与「重要挽留(1家)」曾被误标同一颜色系，辨识度低

### 数据源缺陷对应
→ **缺陷 B + 缺陷 C**（主因）

### 改进方向

**数据侧（治本）**
| 改动 | 目的 | 做法 |
|---|---|---|
| R 改为连续分布 | 消除"85% 挤在 0" | 把活跃度从二值概率改为**泊松过程**（每家客户一个 λ，决定购买间隔），R 自然形成连续分布 |
| M 加上截断 / 混合分布 | 压缩 max/中位 的 55 倍差距 | 幂律保留长尾，但**加入对数正态的主体**（如 80% 来自 lognormal、20% 来自幂律），偏度从 8.3 降到 1~2 |

**视觉侧（治标，即使不改数据也应收）**
| 改动 | 做法 |
|---|---|
| M 轴改**对数刻度** | `ax.set_yscale('log')`，尾部与头部同时可见 |
| R=0 的点**加抖动** | `x + np.random.uniform(-0.8, 0.8)`，避免完全重叠（并注明"已抖动"） |
| 图例只显示 ≥10 家的类别 | 小类合并为「其他」，或图例移到图外 |
| 用**标记大小**表示 R | 让重叠点的信息量增加 |

## 图 02 · RFM 八分层：客户规模与营收贡献

**表达目标（保持不变）**：看清 8 类客户的**规模分布**与**营收贡献**，判断该把资源投给谁。

### 现状问题
1. **只画出 6 类**（「一般保持客户」「一般发展客户」中的部分为空）→ 与"八分层"的名字不符（缺陷 C）
2. **柱子高度极端失衡**：176 / 116 vs 3 / 3 / 1 / 1 → 后 4 类柱子低到看不见
3. **折线断崖**：86.0% → 12.8% → 0.5% → 0.4% → 0.1% → 0.1%，线性刻度下后段全贴地
4. x 轴中文标签旋转 30° 后仍然拥挤

### 数据源缺陷对应
→ **缺陷 C**（主因：R 不连续导致 8 类中 2 类落空、且分布极端失衡）

### 改进方向

**数据侧（治本）**
- 同图 01：R 改为连续分布后，「R 高于均值」的判定不再只有两种结果，8 类自然都会有人

**视觉侧**
| 改动 | 做法 |
|---|---|

| 营收占比折线改**对数刻度**或单独小图 | 让 0.1% 与 86% 都能分辨 |

| 类别**按营收占比排序**，而不是按当前字典序 | 阅读顺序与重要性一致 |
| 补一行说明 | 注明"共 8 类，本图为非空类别" |

## 图 03 · 客户营收帕累托分布

**表达目标（保持不变）**：证明营收集中度 —— 少数客户贡献大部分营收。

### 现状问题
1. **柱状几乎被压平**：除前 2 根（14.2 / 8.1 亿）外，其余 298 根全部低于 1 亿，视觉上等于一条基线（缺陷 B）
2. **缺少关键标注**：看不到"第 N 家达到 80%"这个最有价值的读数
3. 80% 参考线画在右轴，但左轴没有对应刻度，容易误读

### 数据源缺陷对应
→ **缺陷 B**（柱状压平）

> 注意：帕累托图**本来就要展示头尾悬殊**，所以缺陷 B 对这张图是"预期内的" ——
> 问题出在**用线性刻度的柱状来画它**，而不是数据本身错。

### 改进方向

**视觉侧（这张图主要靠视觉修）**
| 改动 | 做法 |
|---|---|
| 柱子改**对数刻度** | `ax.set_yscale('log')`，尾部长尾可见 |
| 或**去掉柱状**，只留累计曲线 | 帕累托的核心是累计曲线，柱子是噪音 |
| **标注关键点** | 「Top10 占 31.9%」「第 139 家达 80%」「Top20%(60家) 占 61.9%」 |
| 参考线改画在曲线图上并标数值 | 80% / 50% 两条，值直接写在线上 |
| 轴标签统一单位 | 左轴"亿元"，与报告口径一致 |

**数据侧（可选）**
- 若希望头部不那么突兀：同缺陷 B 的处理（幂律 + 对数正态混合）

## 图 04 · 月度营收与单均金额（红点为异常月份）

**表达目标（保持不变）**：同时展示月度营收规模与单均金额，并标出异常月份。

### 现状问题
1. 🔴 **右上角标注「2026-06 / 偏离+120%」与标题重叠**（标注 offset 是固定的 +14pt，而该点正好在最高处）—— 最明显的视觉缺陷
2. **右轴数字带千分位**（`40,000`），左轴是 `30` —— 同一张图两种数字格式
3. **单均金额折线除一个尖峰外全程平直**（缺陷 D）→ 看不出"异常有不同形态"
4. 双轴刻度不相关，柱子与折线的交叉点没有意义，容易被误读为"相关"

### 数据源缺陷对应
→ **缺陷 D**（异常只有 1 处）

### 改进方向

**视觉侧（立即可改）**
| 改动 | 做法 |
|---|---|
| 标注位置**自适应** | 若点位于图表上 1/3 区域，offset 改为**向下或向右**；或直接给标注留出顶部空白 `ax.set_ylim(0, max*1.18)` |
| 右轴数字**去千分位** | 改单位为「万元」（`19.0 / 41.8`）或统一去掉分隔符 |
| 图例移到图外或左下 | 避开折线区域 |
| 异常点**标注两行** | 第一行月份、第二行偏离幅度，与点之间加引导线 |

**数据侧（提升信息量）**
| 改动 | 做法 |
|---|---|
| 植入**多形态异常** | 例如：2026-01 金额 +60%（大单）、2026-02 −55%（促销/缺货）、2026-06 +120%（当前）→ 折线有起伏，检测方法也能展示"双向识别"能力 |
| 保留订单量曲线做对照 | 订单量稳定 + 金额波动 → 才能支撑"异常在金额维度"的结论 |

## 图 05 · KMeans 聚类结果（频次 vs 金额）

**表达目标（保持不变）**：展示聚类结果，证明聚类与 RFM 规则分层结论一致（交叉验证）。

### 现状问题
1. 🔴 **散点退化成一条直线** —— 因为 F 与 M 完全共线（缺陷 A，r=0.999984），二维图实际上是一维
2. 285/300 个点挤在左下角（F<10000, M<2 亿），4 个簇在视觉上分不开
3. 图例顺序是 中价值 → 中低价值 → 中高价值 → 高价值，**不是按价值降序**
4. x 轴上限 70000 被 1 个点撑开

### 数据源缺陷对应
→ **缺陷 A**（致命，且不可通过视觉修复）

### 改进方向

**数据侧（必须改，否则此图无意义）**
| 改动 | 目的 | 做法 |
|---|---|---|
| **让 M 与 F 解耦** | 打破共线 | 单均金额加一个**与规模独立的分量**：`单均金额 = 基准 × (0.5 + 1.2×lognormal)`，并允许**大客户的单均金额也更高**（弱正相关而非完全正相关）。目标把 `r(F,M)` 从 0.9999 降到 **0.7~0.85** |
| 引入"客单价"维度差异 | 让 RFM 的 M 有独立信息 | 让部分低频客户有高客单价（项目型采购），部分高频客户客单价低（耗材型）—— 这是真实制造业的常见结构 |

**视觉侧**
| 改动 | 做法 |
|---|---|
| 换坐标组合 | 用 **R vs M** 或 **R vs F** 替代 F vs M（R 与它们本来就不共线） |
| 图例**按簇均值降序** | 与命名顺序一致 |
| 加**凸包或质心十字** | 让簇边界在重叠时仍可辨认 |
| 坐标改**对数刻度** | 缓解左下角拥挤 |

## 三、改进优先级

| 优先级 | 改动 | 涉及 | 成本 |
|---|---|---|---|
| **P0** | 让 M 与 F 解耦（打破 `r=0.9999` 共线） | 缺陷 A | 改 `make_data.py` 一处金额公式 + 重新生成 |
