# 销售与客户专题分析

基于数仓 ADS 层 106 万行销售订单，围绕**经营异常**与**客户价值**两个主题开展分析，
产出含图表、分层结果与运营建议的完整报告。

**姊妹项目**：数据来源为 [制造业经营分析数据仓库](https://github.com/q2898322792/manufacturing-dw)
（本项目**只读**其 ADS 层，不写回任何表，两者完全解耦）。

## 分析内容

| 主题 | 方法 | 核心发现 |
|---|---|---|
| **经营异常（核心）** | 稳健 z-score（中位数+MAD） | 月订单量稳定（CV=0.125）但**单均金额波动 5 倍**：4 个月异常（+115% / +122% / −58% / +94%），需核实是大单促销还是字段质量问题 |
| 客户价值分层 | RFM（五分位打分 + 八分层） | 客户结构极度分散：Top10 仅占营收 3.5%，Top20% 占 20.6% |
| 聚类交叉验证 | KMeans（numpy 实现，k-means++ + 固定种子） | 与规则分层结论一致 |
| 经营预警 | 分布分析 | 「回款滞后」+「营收缺口」合计占预警总量 70% → 风险集中在资金链 |

## 亮点：把「数据不适用」写进报告

分析中发现本批仿真数据的客户是**同质的**（R 恒为 0，F/M 变异系数仅约 2%），
与真实业务的幂律分布（Top20% 客户贡献 60~80%）不符。因此报告明确标注：
分层流程技术上完整正确，但**业务区分度有限**；时间维度的异常发现不受影响。
详见报告第七节「数据适用性说明」。

> 判断数据能不能支撑结论，是分析的第一步 —— 这比给出一个看似漂亮但站不住的分层更有价值。

## 运行

```bash

python run_all.py        # 取数 → RFM → KMeans → 异常检测 → 出图 → 生成报告
```

## 技术栈

Python（pandas / numpy / matplotlib / pymysql）· SQL

> KMeans 为 numpy 手写实现（k-means++ 初始化 + 固定随机种子），不依赖 scikit-learn，
> 结果可复现、依赖最小。

## 目录结构

```
src/
├── config.py       # 数据库连接（读环境变量）、matplotlib 中文字体
├── extract.py      # 从数仓 ADS 层只读取数（客户 RFM / 月度汇总 / 预警分布）

├── visualize.py     # 5 张分析图表
└── run_all.py       # 一键执行
```
