# 销售与客户专题分析

基于销售订单数据，围绕**客户价值分层**与**经营异常检测**两个主题开展分析，
产出含图表、分层结果与运营建议的完整报告。

**两个数据源**（`--source` 切换，分析代码完全不用改）：

| 源 | 说明 |
|---|---|
| **`sqlite`（默认）** | **项目自带仿真数据集** `data/sales.db` —— `clone` 下来就能跑，**不依赖 MySQL / 数仓** |
| `mysql` | 直连姊妹项目「制造业经营分析数据仓库」的 ADS 层，体现从数仓取数的工程衔接 |

> 两条路径都**只读**，不写回任何库。

## 核心结论

**数据规模**：300 家客户 / 353 天 / **4.9 万行有效订单** / 总营收 **3.99 亿元**（单均 8,076 元）

| 主题 | 方法 | 结论 |
|---|---|---|
| **客户价值分层** | RFM（五分位打分 + 八分层） | Top10 客户贡献营收 **14.4%**，Top20%（60 家）贡献 **54.0%**；八分层 **8 类全部有客户** |
| **经营异常检测** | 稳健 z-score（中位数 + MAD，阈值 2.5 且偏离 ≥ 15%） | 检出 **3 个异常月**：2026-01 **+58.9%**、2026-02 **−56.4%**、2026-06 **+118.5%** |
| 聚类交叉验证 | KMeans（numpy 手写，k-means++ + 固定种子） | 4 个簇的客均营收严格递减，与规则分层结论一致 |
| 客户集中度 | 帕累托分析 | 第 **174 家**达到累计 80%，长尾明显 |

## 亮点一：自带数据集具备真实业务的异质性

数仓项目的仿真数据是**均匀分布**的（每家客户每天都买、金额差不多）→ 用它做 RFM 会得到「各层营收只差 4%」的无效分层。

本项目自带的数据集刻意按真实业务特征构造，并**对四个数据源缺陷做了针对性修正**：

| 维度 | 构造方式 | 结果 |
|---|---|---|
| 金额规模 M | **混合分布**：85% 对数正态主体 + 15% 对数正态头部 | 偏度 1.86、max/中位 12.4 倍（原纯幂律为 8.31 / 55 倍） |
| 购买活跃度 R | **泊松过程**（指数分布购买间隔），底部 12% 客户沉睡 | R 取值 72 个、R=0 占比仅 26%（原二值概率导致 85% 挤在 R=0） |
| 客单价 ↔ 频次 | 客单价为**客户级对数正态**，与规模仅弱相关（弹性 0.15） | `r(F,M) = 0.80`（原 0.9999 完全共线，M 沦为 F 的重复） |
| 异常 | **刻意植入三种形态**：+60% / −55% / +120% | 检出 +58.9% / −56.4% / +118.5%，双向识别能力得到验证 |

> 植入已知异常相当于给检测方法一个 fixture，在文档与代码注释中均已明确标注，不是数据造假。
> 四个缺陷的诊断过程见 [`docs/图表诊断与改进.md`](docs/图表诊断与改进.md)。

## 亮点二：把「数据能不能支撑结论」写进报告

分析之前先判断数据适用性 —— 报告保留「数据适用性说明」章节，
记录上一版数据（客户同质）导致分层失效的教训，以及本数据集的异质性验证结果。

## 运行

```bash
pip install -r requirements.txt
cd src
python make_data.py               # 生成自带数据集（约 10 秒，4.9 万行有效订单）
python run_all.py                 # 默认 sqlite：取数 → RFM → KMeans → 异常 → 出图 → 报告

python run_all.py --source mysql  # 直连数仓 ADS 层（需本地 MySQL + 数仓数据）
```

## 技术栈

Python（pandas / numpy / matplotlib / sqlite3 / pymysql）· SQL

> KMeans 为 numpy 手写实现（k-means++ 初始化 + 固定随机种子），不依赖 scikit-learn ——
> 结果可复现、依赖最小。

