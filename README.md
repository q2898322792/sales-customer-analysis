# 销售与客户专题分析

基于销售订单数据，围绕**客户价值分层**与**经营异常检测**两个主题开展分析，
产出含图表、分层结果与运营建议的完整报告。

**两个数据源**（`--source` 切换，分析代码完全不用改）：

| 源 | 说明 |
|---|---|
| **`sqlite`（默认）** | **项目自带仿真数据集** `data/sales.db` —— `clone` 下来就能跑，**不依赖 MySQL / 数仓** |
| `mysql` | 直连姊妹项目「制造业经营分析数据仓库」的 ADS 层，体现从数仓取数的工程衔接 |

> 两条路径都**只读**，不写回任何库。

## 核心结论

| 主题 | 方法 | 结论 |
|---|---|---|
| **客户价值分层** | RFM（五分位打分 + 八分层） | Top10 客户贡献营收 **31.9%**，Top20% 贡献 **61.9%**（真实业务应有的幂律分布） |
| **经营异常检测** | 稳健 z-score（中位数 + MAD，阈值 2.5 且偏离 ≥ 15%） | 检出 **2026-06 单均金额偏离 +120%**，需核实促销/大单或字段质量 |
| 聚类交叉验证 | KMeans（numpy 手写，k-means++ + 固定种子） | 与规则分层结论一致 |
| 客户集中度 | 帕累托分析 | 长尾明显：头部客户 8.9% / 5.1% / 3.7%…，尾部大量小客户 |

## 亮点一：自带数据集具备真实业务的异质性

数仓项目的仿真数据是**均匀分布**的（每家客户每天都买、金额差不多）→ 用它做 RFM 会得到「各层营收只差 4%」的无效分层。

本项目自带的数据集刻意按真实业务特征构造：

| 维度 | 构造方式 | 结果 |
|---|---|---|
| 金额规模 M | 幂律 `w ∝ i^(-0.8)` | Top20% 贡献 ~62% |
| 购买活跃度 | 与规模正相关，并让底部 12% 客户**沉睡**（60~180 天不下单） | R 取值 0~177 天，有区分度 |
| 单均金额异常 | **刻意植入**：2026-06 抬升 ×2.2 | 验证异常检测方法（检出 +120%，与植入值吻合） |

> 植入已知异常相当于给检测方法一个 fixture，在文档与代码注释中均已明确标注，不是数据造假。

## 亮点二：把「数据能不能支撑结论」写进报告

分析之前先判断数据适用性 —— 报告保留「数据适用性说明」章节，
记录上一版数据（客户同质）导致分层失效的教训，以及本数据集的异质性验证结果。

## 运行

```bash
pip install -r requirements.txt
cd src
python make_data.py               # 生成自带数据集（约 1 分钟，80 万行）
python run_all.py                 # 默认 sqlite：取数 → RFM → KMeans → 异常 → 出图 → 报告

python run_all.py --source mysql  # 直连数仓 ADS 层（需本地 MySQL + 数仓数据）
```

## 技术栈

Python（pandas / numpy / matplotlib / sqlite3 / pymysql）· SQL

> KMeans 为 numpy 手写实现（k-means++ 初始化 + 固定随机种子），不依赖 scikit-learn ——
> 结果可复现、依赖最小。

```

```
