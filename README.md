# 销售与客户专题分析

基于销售订单数据，围绕**客户价值分层**与**经营异常检测**两个主题开展分析，
产出含图表、分层结果与运营建议的完整报告。

**两个数据源**（`--source` 切换，分析代码完全不用改）：

| 源 | 说明 |
|---|---|
| **`sqlite`（默认）** | **项目自带仿真数据集** `data/sales.db` —— `clone` 下来就能跑，**不依赖 MySQL / 数仓** |
| `mysql` | 直连姊妹项目「制造业经营分析数据仓库」的 ADS 层，体现从数仓取数的工程衔接 |

> 两条路径都**只读**，不写回任何库。

## 分析结论

> 📄 **具体数值、推导过程与完整表格见 [`output/销售与客户专题分析报告.md`](output/销售与客户专题分析报告.md)（8 节）**。
> 本节只写结论本身 —— 数据规模、占比、异常幅度这类**会随数据重新生成而变化的数值不进 README**，
> 避免两处数字脱节（数字只维护在报告里一处）。

| 主题 | 方法 | 结论（定性） |
|---|---|---|
| **客户价值分层** | RFM（五分位打分 + 八分层） | 营收高度集中在头部分层；**8 类客户全部有数据**，分层具备业务区分度 |
| **经营异常检测** | 稳健 z-score（中位数 + MAD + 业务幅度门槛） | 检出多个月份的**单均金额异常（含上偏与下偏）**，异常出在**金额维度**而非交易活跃度 |
| 聚类交叉验证 | KMeans（numpy 手写，k-means++ + 固定种子） | 4 个簇的客均营收严格递减，与规则分层**独立互证** |
| 客户集中度 | 帕累托分析 | 长尾结构明显：少数客户贡献多数营收 |
| 数据适用性 | 区分度 + 集中度指标 | R / F / M 三维均通过适用性检验，分层结论有数据支撑 |

## 亮点一：自带数据集具备真实业务的异质性

数仓项目的仿真数据是**均匀分布**的（每家客户每天都买、金额差不多）→ 用它做 RFM 会得到
「各层营收几乎没有差异」的**无效分层**。

本项目自带的数据集刻意按真实业务特征构造，并针对四个数据源缺陷做了修正：

| 维度 | 构造方式（设计） | 为什么这样设计 |
|---|---|---|
| 金额规模 M | **混合分布**：对数正态主体 + 对数正态头部 | 纯幂律会让偏度过大、头尾差距过悬殊，图表被极端值压平 |
| 购买活跃度 R | **泊松过程**（指数分布购买间隔）+ 底部客户沉睡 | 二值概率会让 R 挤在单点（如全是 0 天），八分层里的 R 维度失效 |
| 客单价 ↔ 频次 | 客单价为**客户级对数正态**，与规模仅弱相关 | 若金额与规模同比例，M 会退化成 F 的重复，RFM 白白浪费一个维度 |
| 异常 | **刻意植入多种形态**的已知异常 | 给检测方法一个带标准答案的 fixture，验证其**双向**识别能力 |

> 植入已知异常在文档与代码注释中均已明确标注，不是数据造假。
> 四个缺陷的**诊断证据与修法**见 [`docs/图表诊断与改进.md`](docs/图表诊断与改进.md)，
> 具体数值见报告第七节。

## 亮点二：把「数据能不能支撑结论」写进报告

分析之前先判断数据适用性 —— 报告第七节「数据适用性说明」保留了
上一版数据（客户同质）导致分层失效的教训，以及本数据集的验证结果。
**先判断数据能不能支撑结论，再动手分析。**

## 运行

```bash
pip install -r requirements.txt
cd src
python make_data.py               # 生成自带数据集（客户数 / 天数 / 产品数可在文件顶部调参）
python run_all.py                 # 默认 sqlite：取数 → RFM → KMeans → 异常 → 出图 → 报告

python run_all.py --source mysql  # 直连数仓 ADS 层（需本地 MySQL + 数仓数据）
```

## 技术栈

Python（pandas / numpy / matplotlib / sqlite3 / pymysql）· SQL

> KMeans 为 numpy 手写实现（k-means++ 初始化 + 固定随机种子），不依赖 scikit-learn ——
> 结果可复现、依赖最小。
